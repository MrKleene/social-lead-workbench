## 推荐日常方式

在原仓库两个终端分别运行：

```sh
npm run dev:persistent:backend
npm run dev:persistent:web
```

后台终端管理迁移、API及专用采集worker；前端终端只读取原实例的公开端口并运行Vite。前端Ctrl+C/再次运行不影响API或数据库。后台Ctrl+C等待退出后可再次启动。PostgreSQL/Redis独立常驻，保留原容器、命名卷和端口；应用退出不再停止数据库。没有自动重启Docker Desktop、开机项、launchd安装或权限变更。

仍可用 `npm run dev:persistent` 一键启动，适合日常完整工作台。此模式仍统一停止前端与后台；需要单独刷新前端时使用上面两个入口。普通根目录 `npm run dev`仍是另一套手动开发配置，不应与持久main混用。

可选 `npm run dev:persistent:background -- --backend` 让已有实例的后台脱离工具输出会话。仅后台模式检查API就绪；一键后台模式同时检查网页。输出中的PID对应控制进程，`running.json`分别记录launcherPid、controllerPid与实际后台管理pid；正常停止前须核对本轮身份，不能向陈旧PID发信号。没有自动重启策略。

## 互斥与恢复机制

Mac使用已有系统能力 `flock`、进程组、父子管道，原生代码由本机已安装clang编译。系统互斥在迁移前获取，覆盖迁移、构建及API/worker运行；重复启动在任何业务执行前被拒绝。

控制进程与实际后台分离。原生监督器持锁、创建自己的后台进程组；控制管道EOF或后台退出触发TERM清理宽限期，之后只对本次创建、组长尚未回收的进程组发送KILL。回收组长后不再发送信号，避免PID复用误杀。监督器保留运行锁直到组内进程消失。

后台及受管理的直接子进程继承同一内核锁描述符。监督器本身异常退出时，后台通过专用管道EOF停止整个自身进程组；锁不会因监督器单独消失而提前释放。平台工具通过嵌套监督器保留独立工具组，并继承运行锁；API退出会关闭工具控制管道，清理工具及其同组后代。不对任意系统进程扫描或发信号。新代码没有调用真实平台工具，只有虚构进程测试。

新运行记录为v3：当新监督器取得同一内核锁、核验原实例元数据和API端口后，遗留v3记录可在同次系统启动原子替换。记录本身不再充当永久互斥锁；不是仅凭PID消失或网页端口空闲接管。原有BullMQ执行与账号任务/租约保护保持，不用删掉运行互斥换取方便。

边界：不保证恶意子程序自行脱离进程组且主动关闭继承锁后的行为；工具/浏览器版本仍受原有审阅限制。若内核仍报告锁占用、元数据缺失/不符或进程无法退出，仍拒绝重复后台，不猜测恢复。首次初始化元数据损坏不自动重建。Windows保留原Job Object路径，未把Mac验证算作Windows验收。
