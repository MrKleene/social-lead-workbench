## 一条启动命令

```sh
cd /path/to/social-lead-workbench
npm run dev:xhs:login
```

启动命令先检查本机已审阅的 MCP/登录工具、浏览器缓存及本地依赖。它只创建独立临时 CRM 工作台，不启动平台进程、不生成二维码、不创建平台会话目录。打开终端给出的地址，使用终端显示的一次性 **CRM 管理员**登录；该密码与小红书账号无关，不应保存到浏览器。

在 **账号中心 → 添加账号并扫码**，核对保存路径与用途，勾选本地会话保存说明，再点击 **确认并生成二维码**。此时才为该账号启动独立 MCP，展示由已安装工具从小红书登录页面获取的二维码，由本人使用小红书 App 扫码确认。真实采集、搜索、评论、私信和发送始终禁用。

别名与负责人仍在右侧元数据表单管理。扫码成功只有在状态接口明确返回 `is_logged_in: true` 且带有效稳定 `user_id` 后才绑定；昵称不作唯一标识。账号卡片保留验证结果，业务保持暂停；这个结果是某次检查的证据，不承诺后续登录一直有效。

## 核查到的上游协议

依据本机已有源码快照（目录标识 `a5c8f7799980ba1fdd501999843eb2d17e4c9a9f`）的 `routes.go`、`service.go`、`handlers_api.go`、`xiaohongshu/login.go`，以及已安装构建的预检：

- `GET /api/v1/login/qrcode`：受 Bearer 鉴权保护，成功信封 `{success:true,data:{img,timeout,is_logged_in}}`。`img` 来源是平台登录页二维码元素的 src；源码设定最长等待四分钟，后台等待成功后自动保存会话。
- `GET /api/v1/login/status`：成功信封里的 `is_logged_in` 为布尔值；`user_id` 和 `username` 可能缺失。必须同时有明确登录状态和稳定 ID 才绑定，缺失 ID 进入“待核查”。
- 没有独立取消接口；`delete_cookies` 是删除会话功能，本入口不调用。每次尝试使用独立进程，取消/过期通过停止该进程及其浏览器进程组实现。
- 固定审阅的已安装 MCP SHA-256：`17d57acd1a4f4cad3f2525bd13de40e112cb34594231a10b54b05ced9485cf80`。程序更新需重新审阅，不下载替换程序、不调用旧 18060/18061、不抓取普通 Chrome 会话。
- 接受有大小上限的内嵌 PNG/JPEG 数据图片和至多 240 秒期限；拒绝外部 URL、SVG、文件 URL、损坏图片及未知期限。若真实接口返回其他格式，会明确失败，不把外链当公开二维码，不擅自抓取转换。真实端到端响应仍待本人扫码阶段验证。

## 会话与数据生命周期

新会话目录为项目内 `.local/xhs-qr/<账号ID>/<尝试UUID>/`，目录 0700，会话文件 `cookies.json` 在受限 umask 下生成；公共归属标记 `session.json` 不含凭证。每次尝试创建全新目录，不覆盖或导入任何旧 `.local` 会话。二维码仅在后端内存和页面本地状态中存在，接口 `Cache-Control: no-store, private`；不写数据库、审计、日志、公开链接或 Git。没有持久二维码缓存。

取消、二维码到期、切换模块、隐藏页面或关闭页面会停止等待并移除二维码；浏览器取消请求若未送达，服务端在最后心跳后最多 60 秒内停止（启动/平台请求也各有期限）。页面不自动刷新二维码，重试要用户再次点击确认。取消与扫码可能同时发生：若绑定事务已先完成，返回实际已验证结果；否则迟到成功不能绑定。已写入的本地会话可能保留，**取消不是删除凭证或撤销平台授权**。

按 Ctrl+C：停止本次工作台及登记的本次 MCP/浏览器进程组，删除本次两个 tmpfs 容器。临时 CRM 账号卡片、绑定元数据、用户、审计和队列随容器删除；平台会话目录保留，不自动删除或重新导入。因此下次新建临时工作台不会自动恢复旧卡片或旧会话；持久 CRM/已保存会话的恢复管理不在本轮范围内。`.qa/browser-validation/<本次ID>/` 保留无凭证的运行与清理记录。

不要强制杀死整个启动器；系统断电/SIGKILL可能无法完成收尾。没有后台常驻服务或自启动。不得使用全局 killall/Docker 清理处理未知资源，旧用户栈不受此入口管理。

## 权限与并发

- 所有登录接口只允许已认证管理员，写请求沿用 Origin/CSRF 校验；销售及匿名用户不能生成或操作二维码。
- 数据库行锁、唯一请求键及每账号活跃尝试的部分唯一索引防重复点击/并发。取消可先写入请求键墓碑，阻止迟到的开始请求复活授权。
- 最多三个活跃授权尝试；每次独立目录/进程/随机 loopback 端口/临时传输令牌。令牌不进入命令行、响应或持久文件。
- 登录状态探测串行化，间隔至少十秒；仅在本次可见授权流程内轮询，成功、失败、取消、过期后停止。账号归档也停止等待。
- 数据库对平台、提供方、稳定平台用户 ID 做唯一约束，阻止同一真实账号重复绑定。真实绑定账号不是模拟联系账号，真实采集与发送均未开放。
