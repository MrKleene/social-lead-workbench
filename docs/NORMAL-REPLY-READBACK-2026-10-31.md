# 普通回复的折叠回读与审计确认

实际提交成功后，重新打开帖子可能只展示某条评论的第一条回复。旧驱动仅检查初始评论树，没有展开已有回复；缺失和重复都返回 `RECEIPT_NOT_UNIQUE`。2026-10-31 的只读复查重现了初始 12 条、展开一次后 13 条的变化，新增的唯一回复与提交响应中的 ID、发送者、目标、收件人和正文完全吻合。原始失败没有保存候选数量，不能反推出当时精确的瞬时状态。

驱动源码现在仅在指定回复 ID 缺失时追加一次现有有界只读展开：同一帖子、无根评论滚动、最多 100 条评论、12 次展开操作、5 秒窗口。已存在重复 ID 或缺失绑定立即阻断，不尝试修复身份冲突；仍不存在则明确返回 `RECEIPT_NOT_VISIBLE`。不会重新提交。此驱动修改已离线测试，**未安装新二进制**；正式组件仍采用此前批准的固定哈希。

`NormalReplyReconciliation` 是无发送能力的内部审计确认器。它要求原普通任务 UNKNOWN、完整原始平台响应、已停止的执行器、同账号独立只读身份检查，以及持久化审计中唯一的回复和原评论。逐项比对 ID、账号、帖子、父评论、收件人、正文和原评论文字后，仅更新该 attempt/job 为 CONFIRMED，并追加审计。原 UNKNOWN 轨迹、额度、收件人锁、暂停和规则开关均保留。没有暴露自动发送或任意人工确认接口。
