关联 REQ-007/011/015/016/020/021/024/033。承接 `7b21dc1` 普通自动回复接入：新增可选、持久化的有限验收范围，实际执行仍走普通 API、CollectionService、AutoReviewService、ReviewEvaluationService、AutoContactService 和 LocalXhsReplySender；没有调用 single-reply operator，没有为普通长期使用加一条永久额度。

## 行为与边界

管理员可创建一个限期验收范围，固定：采集配置及版本、一个已保存帖子及平台帖子 ID、一个采集请求键、采集账号、唯一回复账号、原样话术/规则哈希、匹配策略/模型/价格版本、允许的评论与接收者元组，以及输入/输出和费用估算限制。最多一个活动范围，期限最多 30 分钟。开始时必须没有其他已开启回复规则、自动匹配方案、在途外部任务或设备租约；不会静默取消旧任务来腾出范围。

- 普通定向采集 API 使用该请求键，只能重读指定已保存帖子、一个窗口；不回退搜索。首次绑定 runId，重复请求返回同一运行。并发/异键/跨配置/错账号均不能开始第二个运行。
- 同一平台帖子重采可能生成新的不可变存档版本，因此同时固定原保存引用与本轮 capturedPostId，而非误用旧存档 ID。模型和发送绑定本轮 runId、新存档与实际评估 reviewIds，历史高分结果不会被扫入本次队列。
- 全帖待评评论仍为一次模型请求；容量不足直接阻断。模型请求的持久 claim 在外发前提交到数据库。任何失败、未知、进程中断、冷却结束、日期变更都不返还这一机会；手动/旧模型入口也不能在该范围内绕开。
- 发送总机会在调用 sender 前持久占用。即使 sender 确认未发送、释放日额度，也不返还本次总机会；最多调用一次 sender，失败/未知/风险不会自动换号或换收件人补发。独立日额度、去重及 UNKNOWN 锁继续执行。
- 每个关键边界重新核查期限、当前账号/策略/模型和来源。过期保持阻断，绝不自动恢复无限制调度。关闭范围会关闭绑定的自动匹配和回复规则、请求取消尚未完成的本轮采集，保留全部 claim 和账本。已经进入外部请求的调用仍可能结束，关闭不是撤回已发送内容。
- 关闭后的旧 run 仍不能再用此范围调模型或发回复；正常新 run 可按普通产品授权继续使用。新建范围需要新 ID、新请求键及显式管理员授权，不能重置同一范围。

## 费用：可执行的是估算门槛，不是账单硬上限

新增 `estimateWholePostCost`，复用整帖容量检查的 UTF-8 保守输入估算及实际请求的 `max_tokens` 输出上限，使用仓库已审阅的数值价目、对应输入阶梯计算，不假定免费额度或缓存折扣。`costEstimate` 随预览返回，模型 claim 的审计记录也保留该估算。

范围必须明确 `maxInputTokens`、`maxOutputTokens`、`maxEstimatedMicros`（一元=1,000,000 micro-yuan）。估算超限、模型或价格版本变化、未知价目都会在凭据读取/HTTP 之前阻断。输出限制落实到既有 `max_tokens`；输入限制基于本地保守估算，不是供应商 tokenizer。返回固定 `billingHardCap:false`：供应商实际计费及未来价格变化不受本机控制，不能承诺人民币账单硬封顶。没有调用供应商接口获取实时价格，也没有以当前账单数据进行真实验算。

本轮生产只读核对的已保存模型为 `qwen3.8-flash`、配置版本 2、价目版本 `beijing-2026-10-21`；原全局每日调用次数为不限。没有改动该设置。未来有限验收仍独立最多一请求，且需要用户确认估算门槛，不能继承“不限次数”作为本轮付费授权。

## 管理员 API 和正常操作顺序

1. 普通设置入口保存匹配与回复配置并保持关闭；先核对具体原文、目标范围和模型版本。只保存不发出外部请求。
2. `POST /api/auto-contact/acceptance`，需要现有管理员会话、Origin/CSRF 和 `normal-automation-acceptance-once-v1` consent。请求字段由 `normalAcceptanceInput` 严格校验，不接受提高总提交数/调用数的参数。其 scope 绑定下一次正常开启产生的版本；中途编辑或额外切换使其失效。
3. 用原有 `/comment-review/policies/:id/automatic` 和 `/auto-contact/rules/:id/enabled` 开启所绑定的配置。范围存在时不允许开启其他配置。没有逐条人工审核。
4. 用普通 `/collection/configs/:id/runs` 启动，传入范围内的 requestKey、采集账号和 `readPlan:{rounds:1,postsPerRound:1,commentPages:1,savedPostId}`。随后由普通 worker 自动匹配、选择范围内高分充分评论、领取并发送；看普通 `/automation` 结果与 `/reply-history`。
5. `GET /api/auto-contact/acceptance` 查看 scope、已绑定 run/存档、模型和发送 claim。`POST /api/auto-contact/acceptance/:id/close` 关闭；同 ID 永不重新 arm。这里只是管理验收范围，没有新增独立发送入口。

没有活动范围时普通产品行为不变；本轮不修改既有页面布局。新接口受管理员/CSRF/版本保护，原设置 UI 回归继续覆盖普通使用。
