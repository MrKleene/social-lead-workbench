本次沿已审查的 read-through 补丁链增加同一页面的续读：不是重新打开帖子并再次读取第一页，也不是无限放宽单次预算。旧 MCP / 旧记录兼容；没有 `crm-comment-continuation-v1` 能力声明时不发送新参数。

## 行为与安全边界

- 每个已授权账号的 MCP 子进程最多持有一个浏览器页面。一个窗口结束后，工作台先把确认读到的原文及该窗口证据 checkpoint 到现有 JSON 存档，再使用同一页面继续。
- START / RESUME 复用既有登录核验、设备归属、任务互斥与只读工具策略。随机续读句柄绑定同一帖子及访问引用，每次使用即失效并轮换；句柄只在进程内，不进数据库、日志、审计、LLM 或用户界面。结果不确定不重复请求。
- 每窗仍最多 3 次根评论滚动、12 次回复操作、15 秒。只在确有新增、且因窗口滚动/回复/时间预算停止时续读。最多 8 窗、页面绝对寿命 2 分钟、空闲 45 秒；既有整任务 32 请求、150 秒、100 评论及单帖 40 根/100 评论/每根回复准入 30 的安全界限仍有效。
- 因而本候选解决超过 **3 次滚动、12 次回复操作或 15 秒** 的可续窗口；**不代表超过 100 评论/40 根等硬范围也已实现任意全量续读**。这些范围仍明确 PARTIAL，不调数字凑总数。
- 平台限制、取消、身份或正文冲突、无进展、未知响应不会自动续读。已确认窗口保留。进程重启或租约过期后不恢复内存页面；重新读取是重新打开后去重，不能称为持久游标续传。

## 证据与完整性

每窗同时保存尝试次数、真正成功的点击/滚动次数和已读树增长。增长不是数据库新入库条数。分窗证据跟随该任务与稳定帖子 ID，不用新帖子快照替代旧任务。

增加已知评论区 THE END 可见、剩余展开控件数量和 DOM 根节点范围一致性证据，仅用于区分“可见区域已到末尾”和“平台全部评论”。缺少每层声明或平台总数不一致时仍不升级 COMPLETE。

原文 41 / 可见 38 的差额原因仍未知；平台隐藏、删除、审核、权限范围的内容无法通过数量推断。已验证另一帖 42 条（22 主评、20 回复），第一次新增 21，第二次新增 0，原有数据保留；这是真实旧安装版本的验证，不是本候选已上线验收。

## 直接回复目标：仅结构取证，不猜映射

页面已证明部分回复针对某个中间回复，而已有 `parentId` 是所属根讨论。普通浏览器工具本轮不可用，现存 MCP 强类型转换会丢弃其他字段。因此本候选在转换前，仅检查固定列举的 `targetComment` / `replyTo` / `parentCommentId` 等候选拼写及固定 id/userInfo 子路径，记录节点序号、类型和它是否等于已加载评论/作者的标识（仅序号/计数）。这些名称是待核实的候选，不是已认定的语义映射。

不遍历任意键、不输出原始 ID、昵称、正文、图片地址、访问参数或登录资料；最多 200 节点、256 项结构记录。结果经严格 schema 进入本次覆盖证据、受保护单帖诊断和审计，默认折叠。旧数据不回填、不改内容去重哈希、不送模型。

真实字段及直接回复语义仍待一次受控样本验证，未据作者或正文猜测，也未将结构父节点冒充直接目标。
