# 采集当前任务与历史分离 · 2026-10-22

关联 REQ-002/007/031/033。前端修复基线 ead4937，不改变此前后台部署记录。

## 问题与修复

进度流原先在找不到 activeRunId 时回退 runs[0]；主按钮也以 runs[0] 是否终态判断完成。因此未开始新任务就显示历史失败和旧计数。诊断时任务总数仍为 4，最新记录为旧 FAILED / INVALID_DATA、1 帖 20 条内容，不是新采集。

- 默认仅显示服务端 QUEUED/RUNNING，或本次可见访问明确启动/观察到的任务；其完成、失败、暂停结果仍在此次访问显示。
- 无当前任务显示「尚未开始」。终态历史在「上次采集」/「运行历史」折叠区保留时间、状态，点击后明确标为历史，可返回当前任务。
- 当前任务选择仅为组件内存状态，离开采集模块或切换配置重置，不写浏览器持久存储，更不修改数据库历史。
- 活动指针缺记录、初始化中、列表/详情读取失败都不能放行新采集。详情缓存不能覆盖列表新状态，晚到的启动返回不能归入别的访问。
- 配置以 URL 选择为准；设置抽屉保存时保持挂载，不因刷新丢失保存回调。
- 原文仍按任务 id 关联；不把别的任务存档归入当前消息。采集授权、账号/设备校验、LLM 可选和独立采集信息入口不变。
