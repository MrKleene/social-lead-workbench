# 小红书真实登录准备入口（2026-10-20）

> 后续已实现工作台内扫码入口，见 [账号中心扫码说明](XHS-QR-WORKBENCH-2026-10-20.md)。本文保留旧分阶段命令及当时的验收边界。


本轮实现并验证的是**安全准备入口与离线集成**。没有执行真实扫码、保存平台会话、启动真实 MCP、采集或发送。工作台没有集成二维码登录；独立登录和工作台接入分阶段进行。账号中心仍是模拟元数据管理，不能把卡片状态当成平台登录证明。

## 命令与边界

| 命令 | 行为 | 平台连接 |
| --- | --- | --- |
| `npm run dev:mock:isolated` | 独立临时 MOCK 数据库和工作台 | 无 |
| `npm run dev:mcp:offline` | 独立临时工作台与虚构 HTTP MCP | 无 |
| `npm run dev:mcp:isolated` | 上一命令的兼容别名 | 无，绝不是真实登录 |
| `npm run xhs:real:prepare` | 检查程序、浏览器缓存、会话路径、环境、端口；打印后续步骤 | 无，不创建会话目录 |
| `npm run xhs:real:login` | 交互确认后打开独立登录浏览器；扫码后可保存新会话 | **需用户随后明确执行并扫码** |
| `npm run dev:xhs:real` | 再次交互确认后，启动独立 MCP 与临时登录验证工作台 | **需用户随后明确执行**；仅手动登录状态检查 |

从项目目录运行唯一的准备命令即可：

```sh
npm run xhs:real:prepare
```

默认会话名 `test-1`，MCP `127.0.0.1:18162`。可加 `-- --session my-test --port 18163`；三个阶段必须使用同一名称和端口。拒绝 18060、18061、已知旧栈端口、占用端口及路径穿越；不会改端口后偷偷复用其他服务器。

## 人工下一步（本轮未执行）

1. 阅读准备命令打印的用途与路径，然后在自己的交互终端运行 `npm run xhs:real:login`。输入终端要求的 `LOGIN test-1` 才会启动程序。独立浏览器打开后由本人决定是否扫码。没有 `--yes` 或无人值守模式。
2. 会话将保存在项目 `.local/xhs-real/test-1/cookies.json`。程序可能在扫码前写入初始化会话数据；文件存在和程序退出码都不代表已经登录。失败/取消的目录也保留，不覆盖；重试使用新会话名。
3. 要用这个已明确批准的会话验证工作台接入时，再运行 `npm run dev:xhs:real`，输入 `CHECK test-1`。此时才允许安装好的 MCP 读取**这个新目录**的会话；不会读或复制旧目录 Cookie/Token。服务只绑定 loopback，传输鉴权令牌每次随机生成，仅在进程内存和子进程环境中使用，不放到 URL、命令行参数、日志或配置文件。
4. 打开终端打印的临时工作台地址，用终端显示的一次性虚构 CRM 管理员登录。该 CRM 登录与平台登录是两件事；不要在浏览器保存一次性 CRM 密码。在采集页面点击“手动检查登录状态”。只有这次明确操作才发出一个有限的状态探测；结果记入临时审计，不能代表持续连接。
5. 终端按 Ctrl+C 停止。仅结束该次启动的 MCP/工作台进程和两个 tmpfs 容器；临时 CRM 用户、数据库和队列随停止删除，**平台会话保留**。不会修改或清理其他工作台。没有常驻服务、自启动或计划任务。不要使用 `killall` 或全局 Docker 清理。

如果终端被强制杀死而来不及收尾，锁文件可能留下；入口拒绝继续。检查原终端与本次 `.qa/browser-validation/<id>/running.json`、`cleanup.json`，人工确认归属后处理。脚本不会根据过期 PID 杀进程、自动删除旧锁或接管未知数据。保留平台会话的删除或重新授权需用户明确决定。

## 准备检查与限制

- 目前只支持本机已审阅的 macOS arm64 登录/MCP 构建。两个二进制 SHA-256 固定在 `scripts/real-mcp/core.mjs`；更新后停止并要求重新审阅，不直接接受新程序。
- 准备入口也要求项目本地 Prisma/tsx/TypeScript/Vite 已安装，不用全局命令或自动补装。已核对的浏览器缓存版本 `148.0.7778.215` 必须存在且可执行；缺失即停止。启动器不安装软件、不拉取镜像。底层已安装工具自身有自动下载行为，因此每个实际启动阶段重新检查缓存；运行期间请勿删除缓存。
- 会话根目录和子目录为 0700，公共归属标记及会话文件为 0600。检查所有者、符号链接、硬链接和独占操作锁。预检查只读取**新入口的公共归属标记**与文件元数据，不读取会话正文。
- 继承环境采用最小白名单；遇到已有 `XHS_*`、`COOKIES_*`、`AUTH_TOKEN`、数据库、代理、DOTENV 等设置即拒绝，错误仅打印变量名。不要 `source .env`；使用干净终端。启动器不更改用户环境。
- 工作台模式强制 `XHS_MCP_LOGIN_ONLY=1`：服务端配置创建、任务启动和 worker 执行均拒绝采集，MCP 传输只允许 `check_login_status`。禁止搜索、详情、二维码、登录、评论、发送；不启动采集 worker。普通 MOCK 和离线 MCP 模式继续可用。
- 上游安装好的 MCP 本身包含其他工具，本入口不修改其程序。工作台调用白名单与每次随机传输鉴权限制本入口；不能据此声称上游软件本身已变成只读软件。
- 真实扫码、登录后状态响应、真实限制/验证码、平台账号与账号中心的绑定尚未现场验证。本轮不启用真实采集或发送；不要把离线夹具的“READY”当作真实账号证据。
