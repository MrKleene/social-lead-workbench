# 专用电脑设置：Mac 单设备闭环

> 后续更新：持久入口已加入批准账号的单次只读采集，见 [账号只读联测说明](ACCOUNT-READ-COLLECTION-2026-10-20.md)。下文“采集关闭”描述属于此前阶段；评论和私信发送仍关闭。
本版在账号中心增加仅管理员可见的“专用电脑设置”。日常命令仍是 `npm run dev:persistent`；首次使用扫码/保存会话核验前，管理员需要在 UI 审阅并批准执行设备。启动命令本身不会创建设备私钥、注册设备或申请二维码。

## 用户最小操作

1. 在专用 Mac 运行 `npm run dev:persistent`，打开终端提供的 loopback 地址并以 CRM 管理员登录。
2. 进入账号中心 → 专用电脑设置，核对设备名称和执行机凭证根目录。
3. 勾选批准声明，再点击“批准注册专用电脑”。只有该明确操作才生成本机设备认证私钥并绑定公钥。
4. 设备显示“在线 · 签名已验证”后，可添加账号并扫码。扫码面板明确显示实际执行设备及保存位置，另需确认平台会话保存用途。

当前仅支持 macOS ARM64 + 本地 APFS。Windows 显示“未支持 / 未验证”，没有安装器或可运行实现。`ExecutionAdapter`/`DeviceCapability` 预留其他系统能力边界，但不能把接口预留理解为已支持。

`dev:persistent:offline` 仍是完全独立的离线环境；UI 明确说明虚构验收身份，不连接平台。旧临时真实扫码入口现在拒绝执行，提示改用持久工作台并批准专用电脑；原临时离线演示保留。真实采集、评论、私信始终关闭。

## 身份与在线状态

- 管理员身份来自现有服务端会话、角色和 CSRF 校验；设备身份使用独立 Ed25519 密钥，不复用管理员密码或浏览器会话。
- 设备私钥只保存在执行机实例的 `device-keys/<keyId>.json`，目录 0700、文件 0600。数据库存公钥、keyId、批准者、批准/撤销时间和目录元数据；响应和审计只显示公钥指纹，不含私钥。
- 每次认证使用新的随机挑战，签名内容包含设备 ID 与 keyId。服务端验证签名，单凭设备名、IP 或 UUID 无法认证。没有允许客户端自行上报“在线”的 HTTP 接口。
- 本版是 **API 与 Mac 本地执行适配器同机** 的闭环：启动和每 10 秒进行本机设备签名证明，不访问任何平台。在线显示要求最近 30 秒认证成功且属于当前 API 运行期；投递前再次验证，不能拿旧“在线”标签绕过认证。
- 密钥缺失、损坏、提供方不匹配、签名失败时离线，停止本次执行并把会话标为待验证，不重新生成密钥。重启复用已经批准的设备密钥，不自动批准新身份。
- 这不是硬件证明或安全芯片存储；本机 OS 用户及进程仍是可信边界。拥有同一 OS 用户权限的恶意进程属于后续系统加固范围。不得复制私钥到服务器或其他电脑。
- Windows、独立远程 Agent、服务器部署、跨机器配对、远程挑战传输、硬件密钥库、自动密钥轮换均未实现或未验证。第一版不新增远程端口或系统权限。

## 单设备与执行隔离

`ExecutionDevice` 用数据库部分唯一索引保证只有一台启用设备。注册/目录变更/执行预留/撤销共享数据库锁，避免并发绕过。所有设备管理接口只允许管理员，严格请求结构与现有 CSRF/Origin 验证保持有效。

`DeviceExecutionLease` 按账号唯一，扫码与保存会话核验共享该租约，防止同账号并发执行。不同账号的目录是 `<批准根目录>/<账号ID>/<会话ID>/`，路径和公开归属标记都验证账号边界。`AccountSessionReference.deviceKeyId` 将引用绑定到已批准的设备密钥代际；同 UUID 的不同密钥或旧的空 keyId 不能继承信任。

任务开始前认证失败即拒绝；根目录变更遇到运行租约直接阻止。结果提交前再次检查设备未撤销、keyId 匹配、执行租约有效，防止撤销后的迟到结果写成已验证。最大任务租约 5 分钟，QR 与核验还沿用更短的自身期限。异常中断留下的租约不会自动抢占，最迟过期后才允许新任务；旧实例锁仍需人工确认没有存活进程。

管理员明确勾选撤销后，数据库撤销即时生效，本进程的等待/核验任务收到中止信号，已关联账号降为待验证。业务记录、平台会话目录和旧私钥文件全部保留；旧密钥不再被接受。已有会话时，本版不提供静默重新批准或自动换密钥恢复流程，需要单独确认迁移/重新登录方案。

## 凭证根目录

首版可配置的是执行机当前实例私有区域下的一级独立目录，例如：

```text
<项目>/.local/persistent/main/credential-roots/default
<项目>/.local/persistent/main/credential-roots/my-accounts
```

离线模式使用 `.local/persistent-offline/<实例>/credential-roots/`。UI 输入的是执行机路径，没有浏览器本地目录选择器。API 验证绝对规范路径、允许前缀、独立目录名、完整祖先链无符号链接、目录归属和私有权限、APFS 文件系统，并写入/删除一个自有探测文件验证可写性。

拒绝共享/网络卷、已知云同步位置、外部位置、`..`、相对路径、符号链接和宽松权限。未识别的第三方同步软件不在自动检测保证范围内，管理员仍须确保整个实例目录不被同步或共享。本版不允许在设置里自由选任意磁盘或服务器路径。

仅在无运行任务、无已有会话引用且当前与目标目录均为空时可换根目录。任何账号引用（包括归档账号）或遗留目录内容都会阻止变更；取消扫码后留下的空账号目录也不会被自动清理。不会读取或搬运 Cookie，不会借更改路径导入旧会话。注册时必须选择空目录。

设备认证私钥与平台会话是两种不同凭据：前者在 `device-keys/`，后者在批准的 `credential-roots/`；均不属于业务数据库备份。业务库备份包含公钥和根目录元数据，不会使新电脑自动可信。

## 升级和旧数据

新增迁移 `202610200008_execution_devices`：增加设备表、账号执行租约、会话引用 keyId。持久入口只迁移自己的实例；本次开发未启动用户真实实例，也未迁移或删除旧测试数据。

已有 UUID-only 会话引用保留但不自动信任、不读取其 Cookie、不绑定到新密钥。旧引用会显示需核查/设备不匹配，并阻止相同设备的静默注册恢复。迁移、凭据导入、旧文件清理和重新授权流程均不在本次范围。

原持久化数据、管理员和启动命令保持不变；新要求只是扫码前的一次明确设备批准。若原实例已有旧会话而无法批准，保持它不变并另行确定恢复方案，不要删除数据或手工修改 keyId。确需空白环境，可由用户明确选择新的 `--instance` 名称；这不是迁移，不会搬入旧记录。

## 验收范围

只在独立的虚构数据库、虚构设备密钥和离线平台驱动中测试。没有生成生产长期凭据、绑定真实设备、读取/搬运已有 Cookie、申请真实二维码、安装新软件或调整系统安全配置。

覆盖管理员/销售/匿名/CSRF、缺少批准声明、伪造候选设备、签名与挑战重放拒绝、单设备并发、路径穿越/符号链接/不安全权限/非空目录拒绝、同账号执行互斥、任务期间目录变更拒绝、已有会话拒绝换根、撤销中断与迟到结果防护、旧 UUID 引用和跨设备拒绝、密钥缺失离线、双启动不重新注册、数据保持及独立业务备份恢复。
