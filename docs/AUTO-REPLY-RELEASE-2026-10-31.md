# 正常自动回复发布候选

本提交是发布候选，不能只拉取应用代码而不安装匹配组件。运行更新与新二进制安装尚待本次明确批准；现有正式实例仍保持旧版本、规则关闭。

## 行为

- 普通发送回读在指定回复 ID 不可见时，执行一次有界评论展开，然后重新核对 ID、发送者、收件人、父评论、帖子与正文哈希。多条同 ID、绑定缺失、超时或身份不符仍不能确认成功。
- 独立 `workbench_reply_verify` 和普通发送调用同一个 `exactReplyPage.readback`。`CRM_EXACT_VERIFY_ONLY=1` 只注册这一工具，去掉旧 HTTP 操作，仅保留 health/MCP；即使同时提供发送环境变量，也不能注册发送工具。接口无正文输入、无提交方法，最大提交数为零。
- 本次平台回复已通过两次独立回查确认。原失败瞬间未保存候选数量；折叠未展开在同帖复现，但不能声称历史瞬间一定为零条，也不能排除短暂可见性延迟。
- 应用部署能力及固定哈希同步更新；它表示用户可以自主启用，不会改变规则 enabled。正常无验收 scope 的流程允许执行，且只接受启用后新建采集轮次的匹配结果。入队、预留与发送前均检查；旧结果重新编辑/评分不补发。
- 设置页明确展示上述边界。100 分原阈值、模板、账号限制、UNKNOWN 锁、跨账号去重、共享日额度、逐帖异常隔离不变。
- 内部 `resolveReviewedNormalPause` 仅支持操作员审阅后的精确控制行版本及确认审计，遇到任何重写、风险、未决任务或新 UNKNOWN 均拒绝。无 HTTP/调度入口，不自动解除暂停；只清除经批准的已解决暂停，不动规则、额度、联系锁和原审计。

## 安装与回滚要求

安装前重查所有队列、登录、采集、匹配、模型、发送和设备租约为空，匹配/回复规则均关闭，且正式 checkout 干净。否则停止。

批准后备份已安装组件和当前正式提交，仅受管停止网页、API 及其后台 workers；保留数据库、Redis、登录和历史。原子替换组件并校验上述哈希，应用快进到本发布提交并受管启动；核对源码与构建哈希一致、服务健康、规则仍关闭。只读验证已确认的唯一回复，不重新采集、不调用模型、不发送、不手动展开。验证成功后，按事先审阅的 xmin/时间/确认审计清除该条已解决全局暂停；任何快照变化则停止恢复。

失败时先停受管应用，恢复旧组件及其匹配的旧应用构建/固定哈希（旧部署能力关闭），再启动；不回滚数据库或 Redis，不撤销确认记录、额度或锁。用户可以在安装验收后自行打开设置中的匹配/回复开关，再启动新采集轮次。发布操作本身不会替用户启用。
