## 业务背景与角色

用户提供面向大学生的选题、开题与论文帮助。主要获客思路是搜索别人的相关帖子，例如“无偿选题”，查看评论中留下的专业、问题和其他需求线索，再由人工核查是否值得跟进。留专业、关键词命中或人工审核仅表示**可能有需求，不等于同意营销**。

- 管理员：管理搜索、话术、账号和负责人，批准专用电脑与凭证目录，审核来源并组织客户交接。
- 初筛人员：查看帖子/用户/评论、筛选待联系线索；初筛不混入销售跟进步骤。当前权限模型只有管理员/销售，是否新增独立初筛角色尚待确认。
- 销售：在自己的电脑登录CRM，处理分配的客户、记录备注/状态/跟进；平台聊天能力不具备时使用平台App。
- 专用执行电脑：保存本人授权的平台登录态并执行允许任务；不是CRM管理员登录本身，也不是按IP识别设备。

目标流程：**设置关键词与筛选 → 手动或将来获准的监控读取 → 展示来源/人工判断 → 待联系 → 未来获准触达或人工记录 → 有意向客户交接 → 销售跟进**。当前只有手动有限读取入口和人工CRM/模拟联系账本；触达、消息同步和自动回复另列需求，不能据此推定已启用。

## 范围与当前验收边界

1. 小红书优先，抖音独立适配；复用CRM不等于复用平台凭据或已有能力。
2. 账号目标约10个；它是目标容量，不是已验证的真实并发数量。账号用途应区分采集、评论、私信。
3. 当前首轮真实验收范围为“无偿选题”、最多3篇帖子、可获取评论窗口、筛选去重入库；关键词可改。真实批准、扫码、读取及重启恢复仍待完成。
4. 约1分钟新评论提醒是未来目标，频率与覆盖受平台能力约束；目前没有持续平台监控，不承诺一分钟或全量。
5. 内部默认10次预算不是平台安全额度。平台限流、验证、封禁必须停止；规避验证码、限制或以换号继续失败任务**不是需求**。
6. 服务器业务数据库+专用电脑执行是目标架构。当前只有Mac同机闭环；Windows、远程执行和销售跨电脑生产部署不能视为已完成。
7. 用户不要求迁移旧测试数据，不等于授权删除。设备更换和已有会话恢复必须明确安排，不静默搬运/导入Cookie。
8. 飞书等“任务完成后等待用户确认”的外部工作通知不属于工作台已实现功能；本文不包含其接入、地址或凭据。
