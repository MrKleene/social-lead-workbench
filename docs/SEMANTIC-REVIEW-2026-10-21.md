# 自然语言审核骨架（2026-10-21）

基线 `684a6ec`；REQ-002/003/004/009/011/017。用户批准实现与正常提交推送；没有批准外部模型传输或真实发送。本轮不改现有深空/中央球体/菜单导航设计，不调整真实教培配置。

## 使用路径与实际能力

1. 搜索设置 → 编辑 → 可选勾选“启用自然语言审核”，填写目标需求与0–100审核优先分数。旧配置/新建配置均默认不启用语义审核；词条规则原行为保留。
2. 搜索词仍用于找帖子。未来获准手动读取的已获取窗口，在旧关键词过滤前为每条评论保存有限原文、实际帖子正文/标题、直接父评论、来源ID与覆盖标志。旧规则仍独立创建原有候选；语义审核不自动创建CRM线索或覆盖旧结果。
3. 采集任务 → “自然语言审核”：分页50条，按分数降序、未评估列后；可展开原文目标、证据、发送阻断。没有模型时显示“模型未配置/暂无可信评分”，无法批准相关，可留备注人工排除。
4. 模型评估有效且语境充分才允许人工确认。人工确认不等于发送，也不会自动加入销售跟进。审核受管理员、CSRF、行版本及配置版本保护，保存审核者、时间、备注和审计。

## 模型与数据边界

- 当前没有生产模型适配器、provider设置入口、密钥读取或外部模型调用。`SEMANTIC_MODEL`只提供依赖注入接口；生产没有注册实现。请求评估在未配置时返回processed=0。
- 本地测试适配器只接受 `isDemo=true` 的虚构快照；`LLM`类型及真实快照均拒绝。测试常量分数只是结构化契约样本，不是关键词评分，也不是实际LLM准确率。
- 未来接入须另行确定服务商/模型、数据授权范围、数据保留、质量样本与限制，并实现对应适配器，不能仅靠设置环境变量偷偷开放。
- 系统提示词与用户目标、非可信帖子/评论数据分开封装；没有模型工具调用/发送能力。输出严格校验ID、唯一性、批大小、整数分数、理由长度、上下文枚举与引用。每条必须引用实际评论原文，所有引用必须在相应实际字段中逐字存在；未知来源、漏条/重复条、伪造引用、额外控制字段均拒绝。
- 缺直接父评论或没有帖子语境强制上下文不足。异常/5秒超时不暴露原始错误，不猜测分数，保持待审核。真实提示注入鲁棒性仍须日后用实际模型验证，当前仅验证数据/指令隔离和结构约束。

## 增量与一致性

采集仍是原有手动有限批次，不扩大读取预算、不等待所有评论、不自动续跑。每个已提交窗口内增量入队；同配置版本和相同原文/上下文快照唯一，重复窗口不重复建立评估。原文/上下文改变或用户保存新配置版本产生新记录，旧记录保留。

测试批评估一次最多10条，乐观版本领取与30秒租约避免并发重复提交；失效租约只有显式评估才重取。评估过程中规则变化丢弃分数；人工排除或另一审核者修改后不能覆盖。记录规则、提示词/测试模型版本及原文快照；没有后台模型重试器。

发送预览独立检查评估/上下文、人工审核、阈值、规则是否过期、同用户多条记录、现有CRM已联系/勿联系与联系账本占用。平台发送能力未实现，未选择或核验发送账号；发送授权缺失，`canSend`在本版本始终为false。此预览不是可复用的真实发送执行器，也不会检查真实平台在线状态或发送消息。
