## 实际变更

1. 共享白名单诊断 schema：固定阶段、受控原因类型和字段路径，最多 10 帖序号/32 内部步骤。未知路径仅为 unknown；不存任意异常消息、值、栈或扩展属性。
2. 区分上游 JSON/结构解析、字段校验、身份/重复冲突、授权检查、原文 checkpoint、最终存档和提交阶段。失败仍为 FAILED，预算、暂停、登录/平台限制仍按原协议处理，不自动重试。
3. 安全投影持久化到现有 CollectionRun.metrics.diagnostic 和 AuditLog.metadata.diagnostic；不新增表/列。管理员现有任务 API 返回，运行详情可展开查看；旧任务无诊断不会补猜。日志仅输出固定事件、合法内部任务 ID 和验证后的诊断，MCP 原始 stdout/stderr 仍不收集。

5. 既有失败清空最终匹配输入的规则保持，已经 checkpoint 保存的原文保留；不会把失败伪装成完成。
