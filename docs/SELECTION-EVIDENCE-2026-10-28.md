# Exact reply selection: verified point and diagnostic evidence

This change is implemented and tested offline. It does not establish the cause of the live `BINDING_EMPTY` failure and does not establish that the new candidate sends successfully. The deployed ac274 candidate safely stopped before input/submission. No new platform access, reply click, input or submission occurred while developing this change.

The saved successful and failed targets both have null parentId. The exact binding guard is byte-identical to the successful b02 version: SHA256 f2bae4d9aec98a4978dd0304ce5386f362ec9621cba15694667173732df089d6. The retained public bundle supports `onReplyClick -> changeCommentTarget(comment) -> note.commentTarget -> submitComment(target.id)`. It is historical evidence, not proof of the current live bundle or current store instance. No saved DOM/event-hit snapshot exists for either run. We therefore retain exact binding; we do not accept nickname, component props or a reply header as a substitute.

The following implementation defects were reproduced offline and repaired:

- The old mouse helper validates an initial hit, jitters the point, then checks only geometry and opacity. An overlay can intercept the final point while those checks pass. Selection now uses the verified point without jitter and checks connected node identity, exact comment ownership, unique scoped reply button, main frame, viewport coordinates, inherited visibility/pointer handling and actual elementFromPoint after moving and again immediately before one physical click. It does not bypass a covered element.
- The selection locator counted child-comment reply buttons under a root even though the DOM guard correctly scoped them by closest comment item. Both now use the same ownership rule.
- The preflight author projection assumed one data-user-id node, inconsistent with the previously observed avatar/image/name triplet. It now requires all scoped author IDs to agree plus exactly one name element, like the send guard.
- Diagnostics formerly lost whether UI activation occurred independently of the store binding. Fixed-enum observations before/after selection and at failure now describe frame, DOM depth, exact button, center hit, component/handler hints, binding shape/status and editor/focus state. These are diagnostics only, never send authorization. Raw text, identifiers, coordinates, URLs, credentials and function bodies are excluded.
- A passive capture listener observes the one authorized reply click, distinguishes exactly one trusted target event from no/foreign/multiple events, then removes itself and releases its CDP object. It never dispatches, cancels or retargets events and does not modify application state. Trusted event delivery still does not prove application handler completion; exact store matching remains mandatory before input.

`workbench_reply_preflight` exposes the same bounded selection observation without any click, focus, scroll, input or event listener. This is the minimum new read-only capability for checking hydration hints, geometry and binding shape. A fresh preflight cannot reconstruct the two already-closed browsers or prove what an earlier click did. If later authorized to continue the one pending target, the passive observer captures the single normal reply selection event in that same session, so there is no extra diagnostic click.

## Recovery after multiple proven non-submissions

Only a fresh explicit one-shot scope can request recovery; no automatic retry is introduced. The verifier traverses every immutable predecessor on the same ledger, up to 16 records. All must be FAILED with identical actor/account/sender/post/comment/recipient/content and protocol, unique correlated authorization/finish events, a valid scope hash and a complete same-protocol NOT_SENT + closed journal. Every link and history pointer must agree, all ledger attempts must be visited, and the root must match the original bounded workflow's hashed authorization and NOT_ATTEMPTED termination. UNKNOWN, success, in-flight, extra cancelled records, missing evidence, disconnected branches, cycles, stale predecessor selection and cross-account changes fail closed. The existing transaction lock serializes concurrent recoveries; replaying an approval returns its existing attempt.

No existing attempt, recipient lock, quota or workflow is rewritten to make recovery possible. Current saved two-failure evidence was replayed against this verifier entirely offline, without creating an authorization or attempt.
