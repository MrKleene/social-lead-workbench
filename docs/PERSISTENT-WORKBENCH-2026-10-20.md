# 持久工作台与本机会话恢复（2026-10-20）

## 日常启动

在项目目录运行：

```sh
npm run dev:persistent
```

终端输出本次工作台地址，所有服务仅绑定 `127.0.0.1`。第一次需要在交互终端初始化 CRM 管理员（隐藏密码输入）；以后使用原管理员、原数据，不重新播种、不重置密码。若已有管理员全部停用，启动器拒绝继续，需要人工恢复管理员，不会创建替代账号。实例名默认 `main`；正常停止后再次执行同一命令即可恢复。

启动前需要本地 Node 22+、已安装项目依赖/生成的 Prisma Client、运行中的 Docker Desktop、已有 `postgres:17` 和 `redis:7-alpine` 镜像。真实入口沿用已审阅工具和浏览器缓存检查；不自动下载、不加载项目 `.env` 或继承平台令牌。混入数据库/代理/平台环境变量会拒绝运行。为防 Prisma CLI 自动加载遗留环境文件，若项目根或 prisma 目录存在 `.env`，入口仅检查存在性后拒绝继续，不读内容、不移动文件；需先人工审阅环境隔离。首次安装/升级代码后先运行 `npm run db:generate`；启动器仅对自己实例执行 `prisma migrate deploy`。

启动本身不访问平台。账号中心“添加账号并扫码”仍需本人明确确认；首次扫码形成可恢复映射。再次启动时显示“本机会话待验证”，主动勾选并点击“验证本机已保存会话”才允许使用该引用执行一次登录状态与稳定 ID 核验。**本轮只做离线验收，没有执行真实扫码、读取真实 Cookie 或调用真实平台。**

当前可编辑关键词/排除词/预算（MOCK 配置），但本入口的采集执行始终拒绝。`XHS_MCP_ENABLED=0`、`XHS_MCP_LOGIN_ONLY=1`，不启动采集 worker，不启用发送。账号内部模拟分配与实际平台会话继续隔离。

## 保存什么

| 数据 | 保存位置 | 正常停止后 |
| --- | --- | --- |
| 管理员、销售、账号元数据、稳定平台 ID、负责人、关键词、线索、跟进、去重与额度账本、审计 | 实例的 PostgreSQL 命名数据卷 | 保留 |
| 队列存储 | 实例的 Redis 命名数据卷，开启 AOF | 保留；不自动开启平台执行 |
| 设备 ID、卷/容器名、固定 loopback 端口 | `.local/persistent/main/instance.json` | 保留 |
| 该实例内部数据库连接密码 | 同目录 `secret.json`，仅本机用户可读 | 保留；不覆盖，不打印 |
| 平台会话 | `.local/xhs-qr/<账号ID>/<会话ID>/`，独立本机目录 | 保留，不上传、不放入业务数据库 |
| 设备/会话引用 | `AccountSessionReference` 表：设备 ID、会话 ID、提供方及验证状态 | 保留；重启降为待验证 |

数据库仅存不透明引用，不存平台 Cookie/Token 或本地绝对路径。业务备份和平台凭据必须分开管理。`.local/`、数据库备份、凭据和运行截图均在 Git 忽略规则中。不要把整个项目工作目录打包上传，也不要对 `.local` 做未经审阅的同步。

Ctrl+C 停止本次 API/Web/登记的 MCP 子进程组，以及本次启动的自有数据库/Redis 容器；**不删除容器或数据卷**。若自有容器在启动前已运行，则保留其运行状态。不会停止其他项目或旧临时栈。

同一实例用独占锁拒绝重复启动，不接管现有进程。卷缺失、归属标签或端口配置不符时拒绝运行，不悄悄新建空库。异常断电或强杀后可能留下 `operation.lock`：先检查原启动终端及该实例公开运行记录，确认没有存活 API、Web、平台子进程后再由管理员处理锁；不要盲删锁或强停未知进程。首次初始化中断、配置丢失/损坏也需人工恢复，启动器不会猜测或覆盖。

## 会话恢复的含义

- `UNVERIFIED`：有可信引用及符合归属/权限要求的文件，但尚未核验。本轮启动只做 stat 与公开归属标记检查，不解析平台凭据。
- `MISSING`：文件或目录缺失；不伪造在线状态。
- `DEVICE_MISMATCH`：必须在原设备/正确提供方核验。没有远程执行或设备认证功能。
- `EXPIRED`：主动核验返回未登录；不自动重新授权或换号。
- `NEEDS_REVIEW`：归属、权限、返回身份缺失/不匹配、异常或超时；需人工处理。
- `VERIFIED`：此 API 运行期内主动核验返回已登录，稳定平台 ID 与原绑定一致；离线提供方始终显示“离线模拟”。这不是永久在线保证。

核验仅管理员可用，要求 CSRF 与明确确认。数据库行锁/租约阻止并发，完成后短暂退避；45 秒超时停止自有进程。核验不生成新二维码、不替换绑定、不自动导入文件。已绑定账号的失效重授权、更换设备与遗留会话关联仍需后续受审阅流程，本版不会自动处理。

API 启动会取消上次遗留的 STARTING/WAITING 二维码尝试，保留审计与历史验证时间。文件存在、历史时间、人工记录均不等于当前平台确认。

## 模拟与旧临时入口

- `npm run dev:persistent:offline`：独立 `.local/persistent-offline/main`，首次交互创建管理员；仅虚构会话文件，不产生真实平台凭据。
- `npm run dev:mock:isolated`、`dev:mcp:offline`：原有一次性模拟环境，停止后删除其自有 tmpfs 数据。
- `npm run dev:xhs:login`：旧的一次性扫码工作台；**不是持久入口**。临时 CRM 消失后，原目录中的会话不能自动恢复为账号。
- 测试专用 `--test-fixture` 仅接受 offline + 随机 `acceptance-<UUID>` 名称；一次生成虚构用户，不用于日常登录。

本轮只读识别到旧临时页面 `http://localhost:54522` 有 12 条线索、2 条配置、2 条跟进、45 条审计；没有读取内容、密码或 Cookie。另一旧临时页面 `http://127.0.0.1:62063` 业务计数为零。二者均原样保留。上述端口和计数是检查时快照，不保证此后仍在线。

**旧临时数据迁移尚未执行**，需另行确认源、目标、停写窗口和备份验证；不能用新空持久库替换旧库，也不要为了迁移先停止旧 tmpfs 栈。新迁移 `202610200007_persistent_references` 仅新增引用表，不把旧 `loginSessionKey` 自动认作可信设备引用。旧 `xhs-real` 与旧临时 QR 会话不会被扫描、读取、复制或导入。

## 业务备份与恢复操作

以下是运维操作说明，本轮仅对虚构验收库演练。实际业务备份/迁移请由管理员选定目标并明确执行。不要将备份提交 Git；数据库中仍含业务数据和 CRM 认证摘要。

1. 从目标实例 `instance.json` **公开元数据**取得 `postgres.container` 和 `id`，核对 Docker 容器标签 `crm.persistent.instance` 与 ID 相同、端口为 loopback、挂载卷与清单一致。不要从旧临时容器提取密码或环境变量。
2. 在管理员控制的私有本地目录设 `umask 077`，用自有运行中容器的本地连接生成一致性备份。下列变量必须填入刚核对过的容器名和新文件路径：

   ```sh
   docker exec "$task_pg_container" pg_dump -U crm -d crm -Fc > "$task_backup_path"
   docker exec -i "$task_pg_container" pg_restore --list < "$task_backup_path"
   ```

   同时在独立受保护位置保存该实例的 `instance.json` / 内部 `secret.json`，供原机灾难恢复使用；不要把 `secret.json` 的内容输出到终端。平台会话目录不在业务备份内，本轮不做其备份或转移。

3. 先把备份恢复到**新建、专用于演练的空数据库**并核对账号、引用、负责人、配置、线索、跟进、去重账本和审计，禁止覆盖现用数据库。验收脚本采用同一测试容器内独立的 `crm_restore_test` 数据库：

   ```sh
   docker exec "$task_test_pg_container" createdb -U crm crm_restore_test
   docker exec -i "$task_test_pg_container" pg_restore -U crm -d crm_restore_test --exit-on-error --no-owner < "$task_backup_path"
   ```

4. 正式切换到恢复数据前，需要单独确认：恢复目标必须是新实例/空库，使用匹配版本的 PostgreSQL，API 停写，再导入并执行本版本迁移。启动器没有一键覆盖恢复命令，也不提供删除现用库/卷的命令。保持原实例可回退，核对后再改变入口。
5. 恢复业务备份不会恢复平台凭据。异机设备 ID 不同会显示设备不匹配；即使原机本地会话仍在，也须主动验证。本版不支持把完整实例清单复制到新设备冒充原设备。

将业务服务迁到服务器、远程设备注册/认证、密钥管理、加密备份和真实会话重授权是后续工程；本轮未购置/部署服务器、开放外网端口或实现远程设备调用。

## 离线验收

```sh
npm run typecheck
npm run build
npm test
npm run test:mock:isolated
# 已有 Playwright 与浏览器时可指定其本地路径；脚本不安装依赖。
npm run test:persistent
```

`test:persistent` 使用全新 UUID 命名的离线实例，完成第一次启动→保存数据→正常停止→第二次启动；核对管理员密码摘要未变、账号与设备映射、负责人、关键词、线索、跟进、审计保留；验证无自动核验、重复启动拒绝、失效/缺失/设备错配、中断取消、管理员/CSRF限制、冷却、桌面/390px和键盘核验。仅自己的虚构库执行 pg_dump/pg_restore，最后按 UUID 归属标签清理自有测试资源。脚本打印截图和检查记录目录，不保存测试密码。

本轮通过类型检查、全工作区构建、113 项单元测试、91 项数据库测试、12 项队列测试和 2 项 worker 检查。Mock-only 按设计跳过 12 项 MCP 集成测试。双启动、备份恢复、桌面与 390px 浏览器验收全部通过；截图与检查记录见本次完成报告。构建保留既有大于 500 kB 的 JS 包提示。实时模型、推理等级和服务层级无法由当前执行器核实；仅能确认任务请求了 Fast。
