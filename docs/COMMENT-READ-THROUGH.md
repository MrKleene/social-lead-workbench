# 评论连续读取：范围、候选与验收

这次把主评论翻页与逐根回复展开交替执行。每次翻页前处理当前已载讨论；滚到已知评论容器底部后，按实际新增唯一 ID / 明确末页信号观察，最多等待 2.2 秒，不再以固定 750ms 后一次快照判定无进展。页面重绘后重新定位控件，重复页不会无限滚动；取消、超时、平台限制与身份/正文冲突仍停止并保留已返回快照。

## 配置和完成语义

服务端 `runtime/comment-read-policy.cjs`：主评滚动最多 3 次、回复控件尝试 12 次、40 根评论、100 唯一评论/回复、每根回复准入阈值 30、每帖内部读取 15 秒。整任务仍有 100 条评论和既有总时限，请求方不能任意扩大预算。回复点击滚动偶然带出的新根节点，在启用主评翻页时需占用一次主评页读取预算才纳入；主评翻页关闭时仍排除并报告。尝试次数不是网站分页数；达到预算必须 PARTIAL，不能保证任意大的帖子都在一轮内读完。

- 主评论末页不等于回复完整；每层声明/实际子节点数保留。
- COMPLETE 仅在本次可访问页面的明确范围证据一致时成立：主评末页、每层计数一致、没有排除/无效/冲突/缺失节点，以及声明总数一致。数量相等本身不充分。
- 零条且总数缺失或无效默认 `EMPTY_UNCONFIRMED`。只有评论区内可见的已核实 `.no-comments-text` 精确提示“这是一片荒地”、空列表、主评末页和有效页面状态同时成立，才能确认当前页面空态；不把未知平台总数改写成 0。
- 缺失叶节点回复计数仍可能 UNKNOWN。平台隐藏、删除、审核中、权限限制内容不能保证获取。
- 保留结构上的父/子关系。现有 MCP 固定 Comment 类型没有独立的直接回复目标字段；界面将结构父节点标作“所属讨论”，不能据此推断直接回复给谁。此项真实字段链路仍需有证据后单独补齐。

## 存档与历史

每次原文 checkpoint 在同一个事务内保存该任务的覆盖证据，使用现有 `CollectionRun.metrics` JSON，无迁移。终态和安全审计沿用闭合白名单，包含每帖序号、唯一主评/回复数及完整 bounded report，不含 URL、平台 ID、原文或身份。失败丢弃规则结果时保留已落盘的覆盖记录。

任务汇总优先展示具体限制，不由最后一篇覆盖；全部逐帖原因仍可在“运行历史 → 任务详情 → 诊断与运行详情”查看。单帖已确认范围不因其他帖子或搜索有限而降级。搜索仍是有限关键词窗口，因此任务 PARTIAL 与某篇评论范围已读尽可以同时成立。历史不会用更新后的帖子快照替代当轮证据；旧历史不回填。
