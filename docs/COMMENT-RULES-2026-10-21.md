## 原因与修复

此前“教培”配置版本1的真实轮次：3篇入选帖子，42条评论/回复观察记录，0匹配；不是没有找到帖子。旧实现将“无偿选题／选题怎么选／开题报告”同时用于帖子搜索与评论匹配，单独的“护理学”等被过滤。首次基线只抑制新增提醒，不抑制候选线索创建。历史42无法准确拆成顶层评论/回复；27为内部读取步骤，包含缓存读取，不能解释为搜索次数或HTTP请求数。

新增可选 `commentRules.version=1`：搜索词只用于帖子搜索，评论使用独立专业名/别名、求助表达、上下文主题词及评论排除词。提供可修改的选题/开题预设。目标需求说明仅保存、展示给人阅读，不执行自然语言指令。

| 输入与已获取语境 | 规则结果 |
| --- | --- |
| 评论“护理”，实际帖子标题含“毕业论文选题” | 高相关；规范专业护理学，记录原词与标题证据 |
| 评论“幼教”，实际帖子正文含“开题” | 高相关；别名映射学前教育 |
| 评论“求指导”，实际直接上级评论含“论文” | 高相关；求助表达与上级语境证据 |
| 评论“护理”，没有主题语境 | 待核查，不因搜索词推断帖子主题 |
| 回复“护理”，直接上级没有获取 | 待核查，即使帖子含主题词也不补猜上级 |
| 命中专业，但上级已表示无需指导 | 待核查，标注否定语境 |
| 评论“护理代写接单”、明确否定需求、招聘等无关用途 | 不匹配，记录对应过滤原因计数 |

优先级：用户排除词 → 固定服务提供表达 → 固定否定/结束表达 → 无关用途 → 无专业/求助信号 → 上下文冲突/否定 → 缺上级/主题 → 高相关。固定表达见 `apps/api/src/collection/comment-rules.ts`，不冒充任意语义推理；可能误报或漏报，仍需人工核查。用户可修改词典/求助/主题/排除词，专业最多30项、每项5个别名；词条最长40字，其他词表各最多30项，说明最多500字。重复或跨专业冲突别名会拒绝保存。

只使用本轮实际获取的标题、正文和直接上级评论，不额外请求上下文。证据保存来源、命中词、规范专业名、最多240字符摘录及缺失标志。不会自动填写话术专业占位符，尚无通用语义模型、专业人工修正或CRM专业筛选。

## 计数与兼容

- 新运行记录保存已提交窗口的帖子、顶层评论、回复数量，高相关/待核查/不匹配与过滤原因计数。分类包含重复观察，不能等同新增线索；同一稳定用户仍去重。
- 数据校验失败等导致结果丢弃时，显示“读取数量不完整，不能视为零读取”。读取计数是本轮接受并提交窗口，不是搜索候选总数；部分结果以停止原因及有限覆盖说明为准。
- 内部读取步骤预算仍32、真实单轮帖子上限仍3。没有扩大平台读取、全量评论分页或后台自动续跑；`load_all_comments` 与 `click_more_replies` 仍关闭。
- 原配置字段为NULL或缺失时沿用旧规则，编辑已有配置默认不勾选升级。用户勾选“启用独立评论规则”并保存才升级、增加配置版本；可取消勾选并保存回旧规则。新建配置默认展示预设，仍需用户保存。
- 已有运行和命中证据不重写；旧统计标明拆分未记录。修改规则不重算旧轮次，未匹配历史原文未保存，不能离线回补。日后用户自行再次读取只针对新获取窗口判断；既有相同来源不重复创建或重写旧匹配依据。
- 首次读取也保存匹配候选，仅不发新增提醒；后续新观察、去重与平台限制停止行为不变。不匹配仅保存汇总计数，不持久化全部被排除原文。
