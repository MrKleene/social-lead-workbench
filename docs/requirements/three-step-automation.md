# 三步自动化与统一设置

主流程为采集 → LLM 评论匹配 → 自动回复。发送处理结束后不等待入站回复，入站回复监控和私信发送仍未接通。

任务状态由只读 `/auto-contact/journey` 汇总完整 run 的审核和规则任务，不使用最近 20 条或当前全局开关冒充历史进度。未知发送、待处理、审核失败、取消/跳过审核与未知状态均不会标为全部完成；模拟结果明确标注。

统一“自动化设置”使用官方 shadcn Tabs：

- 采集：现有关键词组、平台、模式、默认采集账号、单轮帖子上限及本轮范围。每次手动一轮；真实采集当前最多 3 帖。评论采集有既有服务端有限窗口，不宣称读尽全平台。
- 评论匹配：需求描述、已保存目标选择、自动匹配开关及原有付费调用授权。复用全局模型；全部待处理评论整帖审核，超过模型容量整帖停止，不人为截断评论数。
- 自动回复：审核目标版本、门槛、原文内容、评论回复渠道、现有发送账号池及每账号共享日额度。保持原有独立发送授权；保存规则保持关闭。

各组分别保存，没有跨接口原子提交或“全部保存成功”提示。切换页签保留草稿，关闭需确认丢弃；保存失败保留该组草稿并显示错误。更改审核目标后，回复草稿显式确认当前版本。启动校验只要求已开启阶段的必要条件，读取失败会阻止误判开关关闭。

回归范围：完整项目单元/HTTP 测试、类型与构建；隔离浏览器的合成保存/部分失败、条件校验、授权不自动开启、桌面/390px、草稿取消、刷新、历史任务、前后退、嵌套选择、遮罩与 Dock。生产只读验收，不运行真实采集、模型或发送，不变更业务开关或账号状态。
