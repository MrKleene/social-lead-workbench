# 当前产品需求

## 产品范围

系统只管理采集、评论匹配、自动回复、接收消息和平台内会话。支撑页面为首次使用引导、工作台概览、账号设备、配置管理及必要异常记录。

| 能力 | 行为与验收边界 |
| --- | --- |
| 采集 | 按保存账号和范围主动开始；按轮保存帖子、评论和覆盖证据；历史查看不执行新任务；失败或部分读取照实显示。 |
| 评论匹配 | 只使用可靠本轮成员；展示全部评论及真实分数；整轮采集完成后才开始；实际覆盖或审核异常阻止阶段误放行。评论审核按作者聚合：同一账号与匹配方案下多条评论合为一组，人工判断一次，通过时只让代表评论入队。 |
| 自动回复 | 审核完成或人工通过后按评论所属匹配方案的入队配置（阈值与渠道）入队，并冻结规则版本、模板池与账号池；自动发送总开关或渠道开关关闭时等待，开启后按队列调度；历史评论可在评论审核生成待发送；评论与私信模板按渠道隔离，同一收件人各渠道独立首联；资格、额度、幂等、UNKNOWN与风险保护持续有效。 |
| 待处理发送 | 页面分「发送队列」与「需要处理」两个视图；发送队列含待发送、等待额度、排队中、发送中，需要处理含失败、未知、过期，行内显示状态与原因。支持同渠道批量立即发送、失败重试、移出待发送、移除记录与过期重新排队；同一手动批次在列表上方显示批次进度。评论审核页的生成待发送按全部历史审核补齐队列且幂等；入队或评论发布满 7 天过期，过期记录 30 天清理；成功及未知结果禁止直接重发，未知由系统自动只读核对。 |
| 接收消息 | 账号隔离、稳定身份、增量去重、断线状态与系统内未读；区分平台主动事件与补偿读取，不宣称未经真实验证的及时性。 |
| 平台会话 | 保留已有账号、会话和消息展示及对应发送保护；未接通的收件或对话能力明确显示限制，不伪造在线/成功。 |

## 界面要求

首次打开显示使用引导，连接账号或先进入工作台均完成本地初始化；之后直接打开工作台，可从侧栏底部菜单重看引导。仪表盘（工作台概览）与自动化分开。结果页不重复配置。采集操作区仅开始采集、采集与审核设置；配置中心集中管理，设置选择已有配置。三个步骤本身展示当前动作、完成、暂停、失败与未知，不另堆执行日志。居中弹窗、紧凑表格、明确分页、键盘焦点与320px适配；不以删说明隐藏真实风险。

## 权限与数据

单人本地桌面方向采用“下载安装 → 首次使用引导 → 使用”，无需用户另装 Docker、PostgreSQL、Redis 或 Node。桌面版不设工作台账号密码/多用户体系；小红书账号登录、执行授权、额度、去重、未知结果、可靠入站身份和本机安全边界继续保留。配置和业务数据本地 SQLite 保存，模型 Key 和平台凭据保存在受系统保护的用户数据目录。当前仓库不提供旧工作台 HTTP 服务；桌面入口通过受限 IPC 使用本机能力。实现范围与待验收项见 [单人本地桌面版](DESKTOP-LOCAL.md)。

本地桌面不使用账号角色模拟安全边界；可信窗口、IPC 白名单、系统凭据和执行授权继续生效。配置编辑、模型调用、采集与外发授权互不替代。单帖重新读取只采集和审核，不自动回复。共享额度预留与成功数量分开；未知结果保留占用及去重。保留联系风险数据与审计，不重置业务状态。

## 验收要求

隔离模拟覆盖权限、事务、并发、重启、乱序、分页、重复操作、失败与未知。各保留页面桌面和窄屏实际打开检查。真实平台读取、模型和发送必须依照具体授权，不能用构建或mock测试声称真实完成。
