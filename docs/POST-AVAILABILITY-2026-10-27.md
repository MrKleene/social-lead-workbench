# 帖子可访问状态与联系历史（2026-10-27）

关联 REQ-011/015/017/021/032/033。本轮从 a94619f 建立隔离源码副本实现；未迁移、重启或更新正式实例。真实评论发送尚未验收，DM 仍不可用。

## 已实现

- 独立 `PostAvailability` 按平台与精确帖子 ID 保存状态；所有存档版本共用当前状态。不存在检查记录时为 UNKNOWN/待检查，不以已采集或有原文链接推定目前可访问。
- NORMAL/正常、UNAVAILABLE/不可访问、CONFIRMED_DELETED/确认已删除。404、非目标跳转、登录失效、限流、限制页、网络异常有独立原因；无可靠结果为 UNKNOWN。HTTP 管理员入口只允许人工证据，不能伪装为平台确认。删除必须显式勾选确认并填写来源。
- 每次记录都有服务器时间、递增版本、来源、管理员及证据；追加事件历史。不会重标历史帖子，不后台扫描、不新建采集/模型任务。
- 采集信息全量服务端过滤、卡片标签、帖子详情状态抽屉；审核结果和联系记录展示同一状态语义。返回焦点、窄屏、错误反馈与现有雾白绿布局保留。
- 手动“重新检查”当前返回能力不可用和待检查说明，不访问平台、不改状态、不假报成功。用户可打开现有原文入口后，人工记录实际观察。
- 新任务记录冻结帖子/评论快照、审核证据及当时可访问状态；预占时冻结账号 ID、标签、发送者平台 ID（已知时）、接收者稳定 ID、帖子/评论关联。内容、渠道、时间、结果、回执、原额度日期继续独立保存。原文访问 token 不复制到联系快照。
- 台账/身份、台账/尝试、来源配置/采集运行/帖子/评论/评分关系改为 Restrict，阻止级联删除损坏历史；业务仍采用归档。新增状态逻辑没有物理删除入口。
- 新建、领取、派发及真实适配器启动/协商后校验已知状态和版本。保留原有精确帖子/评论/作者验证及候选协议中的提交前检查，不额外打开整批历史，不放宽 URL 或 ID 检查。
- 状态变化在与领取/派发相同的事务锁下终结待执行任务为 BLOCKED_POST。未提交预占只释放其原日期桶一次；ATTEMPTED/UNKNOWN/已确认历史不释放、不改写。不会因一条失效任务挡住其他正常目标。
- 恢复不会复活旧任务；恢复时重设失效时间边界，要求之后的新授权和新审核证据。失效期间授权同样不能用于恢复后补发。任务绑定状态版本，旧单次发送预览还必须明确提供 `availabilityVersion`；旧授权不复活。

## 边界

当前 MCP 不能独立提供可靠、精确的可访问性结果，所以未增加自动重检网络能力，也未从 `TARGET_MISSING`、404 或无评论推导删除。正常状态只表示最后检查时的证据，实际提交仍须原有精确平台核验。

本轮无真实成功发送记录。CONFIRMED/UNKNOWN/删除关系验收全部使用隔离合成夹具，不能作为实际送达证据。旧任务没有完整冻结来源时界面明确显示“历史未记录”，不回填猜测。旧单次测试记录原样保留，未把不可访问样本写入正式业务库。

管理员标记本身记录人工作出的判断，不宣称是平台证明。现有自动审核、发送开关、账号状态和凭据均未操作；本轮浏览器正式只读页需登录，未读取正式开关当前值。
