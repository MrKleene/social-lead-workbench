# 仅 MOCK 工程验收（2026-10-20）

本轮基于 `13e1f80`，只增加工程测试入口与回归，没有新增生产路由、修改认证或改变用户运行环境。

## 执行范围

`npm run test:mock:isolated` 在全新 tmpfs PostgreSQL 17 / Redis 7 上执行，使用随机回环端口；不加载用户 `.env`，不复用任何已有数据库、会话或队列。API、独立采集 worker 的 MCP 开关固定为 0，endpoint/profile 为空。没有启动前端或 MCP 夹具，没有访问真实平台、原 18060 或发送评论/私信。

现有队列测试强制要求空数据库和专用队列名称，不能安全复用用户 `63445`。没有用用户身份直接调用内部 service，也没有向其队列直接投递任务。HTTP 集成测试只在临时库自行生成测试账号，经正常登录接口认证，短期测试会话留在测试进程内；未读取用户密码、cookies 或 tokens。队列测试按既有隔离测试设计使用不可登录的虚构 actor，通过生产 CollectionService 创建运行、实际 Redis/BullMQ 投递，由独立的生产 worker 进程读取 MOCK 适配器并入库；没有伪造采集结果表。

## 结果

- API 与测试 TypeScript 类型检查通过；contracts、API、健康 worker 构建通过。
- PostgreSQL / Nest HTTP：47 通过，9 个 MCP 用例主动跳过。
- Redis / BullMQ / 独立采集 worker：12 通过，3 个 MCP 用例主动跳过。
- 健康 worker：2 项检查通过。
- 共 61 项实际通过；12 个 MCP 跳过不计为通过。
- 结束时队列验收键 0，临时容器 2/2 删除，未留下测试账号、会话或数据库。

## 用户环境与限制

本轮结束时只读检查：`63444/api/health/ready` 返回数据库 ready；用户 `63445` 的“验收专用63445-模拟闭环”仍为 MOCK、enabled=true、0次运行。没有改写或重启该环境，没有新增前端栈。用户终端与临时数据保持原状。

本轮没有操作内部浏览器，页面点击、页面刷新及63445中的采集结果均未验收；通过的是测试库的真实入库与HTTP重新读取。原 IAB 工具不可用/桌面应用访问被拒绝的问题仍在，工程测试不是绕过该限制。63445受保护业务调用没有可复用的免凭据测试入口，本轮停在该边界，不再要求用户循环登录。

真实接入仍需独立确认账号/数据使用范围、MCP服务身份与版本、非18060独立端点及一次有界只读授权；本轮不执行真实联调。
