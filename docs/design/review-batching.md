# 评论审核分批、重试与暂停

评论审核按批调用模型。分批大小、尝试次数和可重试错误由 `packages/domain/src/collection/review-retry-policy.ts` 固定，调用方不能扩大。

## 分批

- 同一帖按 `run_comments.ordinal` 原顺序每 50 条评论一批；每批一次模型请求，只包含该批评论的原文与上下文。
- 正文为空的评论（只有图片/表情或被删除）无法提供逐字证据，不进入请求和完成判定，也不计入已审进度。
- 正文超过 200 字符的评论不送审，单独计为「跳过（评论超长）」，不进入请求和完成判定，也不计入已审进度。上限由 `reviewCommentPolicy.maxChars` 固定。
- 每批 scope 精确绑定 `commentIds`、`segmentNo`、`attemptNo`，并与模型、规则修订、内容哈希一起参与预览哈希和授权校验；执行前逐批重算，任一变化即拒绝。
- `review_batches` 一行代表一次模型调用；重试写入 `attempt_no + 1` 的新行，旧行保留。
- 评论级完成判定：该帖全部可送审评论（正文非空且不超过 200 字符）在同一 `policy_id + policy_revision + model_version` 下各有一条 `COMPLETED` 结果，且 `source_hash` 与当前原文一致；不再要求一帖只有一个批次。
- 预览和重试都从「未审评论集合」切批；已审评论不重复提交、不重复计费。
- 证据校验：引用的非空白字符必须与外发原文逐字一致，空白字符按等价处理（原文可能含 U+2006 等非常规空白，模型会输出普通空格）；纯空白引用无效。

## 单批尝试

- 单批最多 3 次尝试（首次 + 2 次重试）；重试由服务端自动排队，不要求用户逐批确认。
- 重试间隔沿用模型调用节奏：普通失败 30 秒，`RATE_LIMIT` 60 秒。
- 只有确定没有产生模型结果的失败才自动重试：
  - `NETWORK_ERROR`（连接阶段失败，请求未到达模型）
  - `RATE_LIMIT`、`UPSTREAM_FAILED`（429 / 5xx）
  - `INVALID_OUTPUT`、`INVALID_RESPONSE`、`OUTPUT_*`（模型返回格式或内容校验失败）
- 不自动重试：`AUTH_FAILED`、容量/价格未确认、每日额度、规则或预览已变化、本地取消，以及结果未知。

## 暂停与恢复

- 单段 3 次尝试耗尽：该段失败，暂停该帖后续批次；已审结果保留，未审评论不标记为已审。
- 连续 3 段可重试失败耗尽：暂停整轮审核队列。
- 结果未知（请求已发出后超时、断连、进程崩溃或未取得响应）：立即暂停全部模型调用，不自动重试；需人工对账后恢复。
- 暂停记录写入 `review_pauses`（`kind = POST / QUEUE`）；任务页展示暂停原因、已审数量与失败详情。
- 人工恢复：在任务页预览「本轮剩余评论匹配」并重新授权，会清理该帖的暂停记录，只排未审评论。

## 失败原因展示

失败详情记录错误码、错误阶段、HTTP 状态、第几次尝试与耗时，并保留具体校验项（如「第 21 条：证据引用并非对应外发原文中的逐字片段」）；页面按类别显示：

| 类别 | 页面文案 |
| --- | --- |
| 网络连接 | 网络连接失败（可重试） |
| 服务端限流 | 模型服务限流（可重试） |
| 服务端故障 | 模型服务异常（可重试） |
| 返回格式 | 模型返回格式异常（可重试） |
| 鉴权 | 模型鉴权失败（需检查配置） |
| 容量/额度 | 超出模型容量（需调整） |
| 结果未知 | 请求已发出，结果未知（需人工确认） |

自动审核与手动审核使用同一分批、重试和暂停规则。自动审核只对采集轮次（`SEARCH`）生效；补读轮次（`SAVED_POST`）不会自动审核。
