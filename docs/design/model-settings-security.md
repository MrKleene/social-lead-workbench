# 桌面模型凭据与授权

当前产品为单人本地 Electron 工作台，不使用工作台账号密码或旧 HTTP 管理员会话。
首次使用引导只初始化本地业务数据，不创建主密钥文件、不配置模型 Key，也不触发模型请求。

## 保存与使用

1. 从「配置管理 → 模型」输入模型 API Key；无需通过聊天或环境变量传递。
2. Renderer 通过固定 IPC `saveModelKey` 将输入交给主进程；主进程校验可信窗口与方法白名单。
3. `CredentialStore` 使用主进程提供的 Electron `safeStorage` 加密，将密文保存为用户数据目录内的 `.sealed` 文件。
4. 没有可用系统保护时拒绝保存，不创建明文替代文件。测试夹具禁用系统凭据访问。
5. 页面仅返回配置状态，不回显完整 Key 或片段。保存 Key 不测试连接、不调用模型。

业务数据库为 SQLite；Mac 数据目录为 `~/Library/Application Support/SocialLeadDesktop`，Windows 为 `%LOCALAPPDATA%\SocialLeadDesktop`。
凭据文件不在仓库、安装目录、业务数据库或业务备份内。文件写入使用私有临时文件、同步和原子替换，并检查符号链接、文件类型和权限。
实现见 `packages/local-runtime/src/credentials.cjs` 与 `apps/desktop/src/main.cjs`。

## Key 与执行授权

授权不需要用户确认：保存或替换 Key 后，服务端按当前受控型号写入价格版本与原文发送范围。
用户只选择型号；价格版本由受控目录给出，界面不提供单独的价格勾选。
Key 写入失败时旧 Key 与既有授权保持原样，不会留下「授权已撤销但没有新 Key」的半状态。
页面的「已配置」只说明本地凭据文件存在，不证明 Key 有效或模型服务可用。

变更型号会关闭已开启的匹配目标与自动审核，需要重新打开；每日请求次数为空表示不限次数，预算仍按调用次数累计。
匹配目标、整轮自动审核和回复/私信分别授权；模型评分本身不授予发送权限。
关闭授权阻止后续调度，不能撤回已经发送且可能计费的请求。预算、去重和未知结果保护不因替换 Key 或重新打开引导而重置。

当前桌面接口提供 Key 保存/替换，不把旧服务器的删除表单或主密钥恢复命令描述为现有功能。
需要立即撤销服务商 Key 时应在服务商控制台处理，已经发出的请求与历史账单不随本地配置消失。

## 备份与迁移

业务备份排除系统凭据。换电脑、切换系统用户或无法解密时，需要重新输入模型 Key、登录平台并获取来源引用；不能仅复制 SQLite 就宣称凭据已经恢复。
只读旧数据库导出与历史导入保留业务数据和风险证据，不迁移旧模型密文，也不自动恢复执行授权。

旧文件主密钥工具 `model:vault:init` 已移除，不再依赖 `.local/persistent/main/instance.json`。
旧部署命令和历史主密钥说明仅保留在 Git 历史；本次代码清理不读取、迁移或删除设备上已有的主密钥文件。

## 能力边界与验证

系统凭据保护不能抵御已控制同一系统用户或进程内存的程序，SQLite 也没有整库加密。
Mac 系统加密的合成往返已有独立验证；Windows DPAPI、真机安装升级、真实模型权限和收费行为仍需分别验收。
离线 UI 的成功状态不代表真实 Key 可用，不应以模拟结果替代实际服务验收。
