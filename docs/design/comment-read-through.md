# 评论连续读取：范围、候选与验收

这次把主评论翻页与逐根回复展开交替执行。每次翻页前处理当前已载讨论；滚到已知评论容器底部后，按实际新增唯一 ID / 明确末页信号观察，最多等待 2.2 秒，不再以固定 750ms 后一次快照判定无进展。页面重绘后重新定位控件，重复页不会无限滚动；取消、超时、平台限制与身份/正文冲突仍停止并保留已返回快照。

## 配置和完成语义

服务端 `packages/domain/src/collection/comment-read-policy.cjs`：主评滚动最多 3 次、回复控件尝试 4 次、40 根评论、100 唯一评论/回复、每根回复准入阈值 30、每次内部读取 15 秒。每帖另有异常兜底时限：60 秒 + 平台声明评论数 × 1.2 秒，下限 90 秒、上限 40 分钟；到时限保留已读、该帖按 PARTIAL 结束、继续下一篇。整轮上限按本轮各帖预算之和加 5 分钟余量计算，硬顶 150 分钟；每篇开头再用整轮剩余时间夹一次，连续读取每满 10 分钟插入一次 20~40 秒停顿（可被取消打断）。整任务仍有 100 条评论和既有总时限，请求方不能任意扩大预算。回复点击滚动偶然带出的新根节点，在启用主评翻页时需占用一次主评页读取预算才纳入；主评翻页关闭时仍排除并报告。尝试次数不是网站分页数；达到预算必须 PARTIAL，不能保证任意大的帖子都在一轮内读完。

- 主评论末页不等于回复完整；每层声明/实际子节点数保留。
- COMPLETE 仅在本次可访问页面的明确范围证据一致时成立：主评末页、每层声明/已载一致、没有剩余展开控件、没有排除/无效/冲突/缺失节点。平台全局评论计数（页面顶部「共 N 条评论」）可能滞后于已删除或隐藏的评论：它只作为证据记录「平台声明 N 条，已读取 M 条」，不再要求等于已读取唯一数；页面结构自洽即判 COMPLETE。数量相等本身仍不充分。
- 零条且总数缺失或无效默认 `EMPTY_UNCONFIRMED`。只有评论区内可见的已核实空态提示（`.comments-el` 或 `.no-comments-text` 文本以「这是一片荒地」开头）、空列表、主评末页和有效页面状态同时成立，才能确认当前页面空态；评论区显示「加载中」时先等待最多 8 秒再判空，不能把未加载完当空帖；不把未知平台总数改写成 0。
- 缺失叶节点回复计数仍可能 UNKNOWN。平台隐藏、删除、审核中、权限限制内容不能保证获取。
- 保留结构上的父/子关系。现有 MCP 固定 Comment 类型没有独立的直接回复目标字段；界面将结构父节点标作“所属讨论”，不能据此推断直接回复给谁。此项真实字段链路仍需有证据后单独补齐。

## 存档与历史

每次原文 checkpoint 在同一个事务内保存该任务的覆盖证据，使用现有 `CollectionRun.metrics` JSON，无迁移。终态和安全审计沿用闭合白名单，包含每帖读取序号、公开帖子 ID（仅安全字符，不含访问参数）、唯一主评/回复数及完整 bounded report，不含 URL、原文或用户身份。新任务以帖子 ID 关联存档顺序与读取证据；读取接口批量补充当前已存标题用于识别，不把当前内容或计数冒充历史快照。旧任务未记录关联时明确标注，不能按序号或数量推断。失败丢弃规则结果时保留已落盘的覆盖记录。

任务汇总优先展示具体限制，不由最后一篇覆盖；全部逐帖原因仍可在“运行历史 → 任务详情 → 诊断与运行详情”查看。单帖已确认范围不因其他帖子或搜索有限而降级。搜索仍是有限关键词窗口，因此任务 PARTIAL 与某篇评论范围已读尽可以同时成立。历史不会用更新后的帖子快照替代当轮证据；旧历史不回填。

## 构建与真实验证

桌面版使用受审查的本机原生资源与构建清单，构建入口为 `npm run desktop:build:native`，具体平台约束见 [桌面说明](../requirements/DESKTOP-LOCAL.md)。
不沿用旧 API/worker、Redis 或手动替换用户目录 MCP 的部署命令。资源缺失、哈希不符或平台证明不足时保持不可用。

只读诊断入口为「自动化任务 → 新链接单帖只读诊断」：选择已有账号，填写有效原文链接并确认只读检查。
该入口使用固定读取预算，不自动派生采集、模型或发送任务。原文基线应在本次真实验收中独立核对，不能拿旧任务总数或旧时点页面当作当前完整性证据。

验收前确认目标账号、原文链接和只读范围；检查唯一 ID、回复展开证据及实际覆盖标志。失败、未知和预算上限必须如实显示，不自动换号或扩大读取范围。

## 指定已保存帖子重新读取（工作台入口）

采集信息 → 打开已保存帖子 → **重新读取此帖**。明确选择可用账号并授权后，创建普通采集任务；`readPlan.savedPostId` 仅保存当前配置下的存档行 ID，服务器重新核对归属和有效访问引用，不接受调用者提供的网址。直接读取该帖，不搜索、不改动长期关键词配置，不扩大预算。缺少引用时拒绝，不回退到关键词搜索。

该入口与只读“单帖检查”不同：使用已有账号/设备授权、可信窗口 IPC 校验、显式读取确认、任务互斥与幂等机制，沿既有 checkpoint 保存新增原文、复用相同内容；失败时仍保留已落盘记录。不会自动调用模型或发送消息。没有新表、无需迁移；已安装的 read-through MCP 可直接支持，不需另换程序。

新增任务的证据以公开帖子 ID 关联标题与读取序号，旧历史没有关联字段时明确标注，不猜测对应关系。可见主评论末页与逐根回复声明已载一致、但平台总数不一致时，页面结构自洽即判完整，差额按「平台声明 N 条，已读取 M 条」作为证据展示。

离线回归涵盖指定目标无搜索、跨配置/无来源拒绝、账号保护、IPC 边界、幂等与运行互斥、新增/复用、途中失败保留、桌面/窄屏授权与响应不确定时禁止重复提交。真实验收由浏览器对同一旧帖先建立当前原文基线，再仅提交一次此入口；对照本轮新增唯一 ID、回复展开前后证据及落盘，不以旧总数或尝试次数当作成功证明。
