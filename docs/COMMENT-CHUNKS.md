# 分块确认、持久检查点与有限重放（候选，未部署）

本版取代 v1 的整页累计 40 根 / 100 条硬停止：这些现在是**每块新增输出**限制。每块原文写入与检查点更新在同一 PostgreSQL 事务中完成，事务成功才允许下一次 RESUME。不是提高常量后把部分完成改成全部完成。

## 协议与恢复

- MCP 能力 `crm-comment-chunks-v1`；START 可带已确认检查点，RESUME 携带上块确认摘要，FINISH 确认最后一块并释放页面。旧 MCP 没有能力声明时仍走旧协议，保持旧 100 条任务上限。
- 单块最多 100 新评论、40 新根评论、384 KiB 输出；已确认原文不再积存在 MCP 的待确认块中。会话仅保存标识、结构父标识及内容摘要。正文、作者标识、URL、访问引用不进入检查点。
- 同一块在确认前不可变；完全相同的重复 ACK 只返回缓存结果，不再滚动或点击。工作台对结果不确定的外部请求不盲重试。
- `CommentReadCheckpoint` 绑定配置版本、帖子、已授权账号及设备。单调递增 fence 隔离旧工作进程；提交检查 owner、fence、租约、任务取消状态及既有设备授权。取消或事务回滚不发送 ACK。
- 进程重启不能恢复浏览器内存页面。下一次**正常授权**的指定帖子读取，从头有限重放并逐 ID、父关系、内容摘要验证既存边界，不信任数组偏移；确认的前缀不消耗新增输出配额。缺失或冲突的锚点明确停止，不猜测已越过它。
- UI 默认恢复同配置、同账号设备的未完成检查点；“恢复选项 → 从头重新核对”只重置派生检查点，保留所有原文/版本。切换此项撤销本次未提交的授权勾选，不能悄悄改变一次授权的范围。
- 已完成帖子重新读取是新观察；不自动使用上次 COMPLETE 检查点。配置版本变更也不继承旧边界。
- 已存父评论按检查点摘要恢复，仅补当前增量所需上下文，避免跨块缺少父正文造成伪版本。最终比对把已确认前缀纳入 seen 集合，避免把恢复前缀误标为消失。

## 有限预算与未解决的外部边界

每窗仍最多 3 次根滚动、12 次回复操作、15 秒；同页面最多 8 窗、绝对 2 分钟、空闲 45 秒。整任务最多 32 内部请求、150 秒和 800 新评论。持久标识账本最多 2,000 条；单次页面快照上限 2 MiB、深度 8。达到这些边界仍 PARTIAL，明确 LEDGER_LIMIT / RESPONSE_LIMIT / REPLAY_BUDGET 等原因，不宣称无限大帖都能完成。

每个回复控件的准入仍受单次 30 条阈值约束；已加载 30 条不再阻止同一根继续下一小批，但单一控件声明超过 30 仍安全停止。真实平台控件及虚拟列表行为未在本候选上验收。

有限重放无法保证任意深前缀都能在上述时间/窗口内重新找到。锚点消失、内容变化或超预算时停下，用户可经正常入口选择从头核对。不是永久远端游标，也不自动重用旧授权重新启动崩溃的 RUNNING 任务；该任务需通过现有暂停/结束和新的正常授权路径恢复。原文已事务保存，但崩溃前尚未完成的下游规则/提醒处理不属于此检查点的自动重跑保证。

平台 41 / 可见 38 的未知差额、隐藏/删除/权限外内容，以及“直接回复某人”字段真实语义仍未解决。结构父节点不改称直接回复目标。本候选保留上一版受控结构诊断，等待允许的真实样本，不猜映射。
