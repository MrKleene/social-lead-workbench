## 已确认事实与改动

旧入口要求管理员手填设备名称和凭证路径，再勾选确认；它已经有服务端管理员校验、单设备约束和签名认证。因此简化为一个明确批准按钮，复用原授权事务，不取消设备身份，也不把管理员登录视作设备认证。

- `POST /devices/bind` 在解析请求和操作文件前强制管理员身份。只接受本机候选ID与固定同意版本；名称、OS和默认目录由执行程序产生，拒绝客户端路径字段。浏览器UA/IP不用于批准远程设备，远程接入仍关闭。
- 页面展示实际执行电脑、专用用途和授权范围。“一键绑定这台电脑”点击才生成持久密钥并批准；无需手填名称/路径。绑定不触发扫码或采集。高级路径与撤销操作折叠保留。
- PostgreSQL锁与既有单设备限制保证并发/重复绑定复用原身份、版本和单条批准审计；重试前重新验证签名。旧身份不可用时拒绝覆盖，解锁系统存储后手动重试可恢复。
- 销售直接调用绑定、旧批准/目录/撤销、扫码管理、采集启动/停止接口均被后端拒绝。既有销售客户归属、跟进、分配等回归通过。保持账号隔离、执行租约、逐次只读授权及平台限制停止逻辑。
- 已撤销且存在账号引用的设备仍拒绝静默重新绑定。完整跨机换绑/会话迁移尚未实现；本轮不删文件或迁移旧授权。

## 存储实现及边界

新Mac ARM64设备私钥由 `native/macos/device-vault.swift` 调用macOS Security接口写入当前用户默认钥匙串。服务使用专用service及设备ID/keyID定位条目；秘密仅走子进程stdin/stdout，不放命令行或日志。磁盘v2身份文件仅存公钥和元数据。钥匙串锁定、条目不可用或助手失败时拒绝认证，不回退明文。普通启动复用哈希不变的助手二进制，避免无意义重编译改变访问身份。

已有v1私有文件密钥不自动迁移或删除，页面明确标识。离线演示继续使用隔离虚构文件密钥。没有Secure Enclave或物理硬件绑定承诺；同一OS用户/管理员的完整系统控制不属于此应用隔离边界。

新真实模式平台会话默认保存于：

```text
~/Library/Application Support/SocialLeadWorkbench/devices/<设备ID>/credential-roots/default
```

`~` 来自实际执行进程的OS用户。路径要求本地APFS、用户归属、私有应用子目录，不允许符号链接、路径穿越、已知共享/同步区域或不安全祖先权限。旧实例允许区继续兼容，旧会话不搬运。

**平台会话和设备密钥不同。** MCP仍需要私有本地会话文件，保留目录0700/文件0600、按账号隔离和引用校验；本轮没有增加会话应用层加密，也没有核验用户FileVault状态。未知同步软件不能保证检测。Windows当前用户DPAPI仅列为后续方案，未实现或实机验证；Windows/其他执行系统仍禁用，不提供明文替代。

Mac助手使用现有Apple编译工具，无软件下载；当前文件钥匙串API存在弃用警告，需要后续macOS兼容性维护。默认用户钥匙串的实际授权行为尚待用户点击绑定验证。本轮原生测试只使用独立临时钥匙串；不能据此声称用户真实设备已绑定。

## 升级与用户操作

本轮增加后端接口及原生助手，需要用户安排一次同实例重启；代理没有停止当前服务。正在进行扫码或采集时先等待/手动停止，重启会短暂中断网页连接并终止进行中的工作，不自动重试平台任务。

1. 在原 `npm run dev:persistent` 启动终端按 Ctrl+C，等待正常退出。
2. 在同一项目重新运行：

   ```sh
   cd /Users/kleene/projects/social-lead-workbench
   npm run dev:persistent
   ```

   原来若带 `-- --instance NAME`，继续使用原名称。不要改用offline、Compose或新实例，不删除 `.local`、锁文件或Docker卷，不重新初始化管理员。启动器复用保存的实例UUID、业务卷和端口；已有实例缺卷或端口冲突会报错，不应通过删配置解决。
3. 当前工作台仍应为 `http://127.0.0.1:63968/work?module=accounts&view=new`。若输出不同端口，先核对同一项目/实例，不进入新库初始化。
4. 管理员展开“专用电脑设置”，核对实际执行主机后点击“一键绑定这台电脑”。若系统存储拒绝访问，检查本机钥匙串解锁/权限并手动重试；不要重新生成身份或关闭保护。
5. 绑定认证成功后本人扫码；平台稳定ID校验成功才可逐次确认最多3篇只读采集。评论/私信和自动持续采集继续关闭。

只更新前端、后端尚未重启时，页面会禁用新按钮并显示升级提示，不把旧接口误当成绑定成功。无需新增数据库迁移；没有修改现有数据库、管理员或端口配置。
