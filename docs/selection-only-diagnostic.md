# One-selection diagnostic contract

This is an operator-only diagnostic, not send qualification or delivery proof. A newly approved private scope binds the installed candidate hash, account, sender, post, exact comment, recipient and reviewed record/version. It accepts no reply body.

`CRM_REPLY_SELECTION_DIAGNOSTIC_ONLY=1` exclusively registers `workbench_reply_selection_diagnostic` (protocol `workbench.xhs.reply-selection-diagnostic.v1`). It suppresses send tools and legacy HTTP actions, even if a send flag is also set. Its schema requires `maxReplySelections: 1`, `maxInputs: 0`, `maxSubmissions: 0` and rejects additional properties. It is correctly marked as a UI action, not read-only.

The production send driver and diagnostic share `exactReplyPage.openReply`: exact identity/target checks, unchanged `note.commentTarget` binding guard, draft checks, scrolling, final hit verification, one physical click, passive trusted-event observation, bounded binding/editor reads. Only the full send driver owns the input and submit methods. The diagnostic holds the selection-only page capability and stops after observation. The engine and page each reject reuse; the client sends at most one tool call; private authorization consumption rejects restart replay.

Evidence contains fixed categories, bounded viewport dimensions/scroll offsets, initial/scrolled/final binding and editor state, click intent/event, and close status. It contains no body, session credential, raw DOM, event payload or unredacted screenshot. The journal is exclusive, private and fsynced before a possible click. Missing/torn evidence cannot become successful diagnostic acceptance. `POST_SELECTION_BINDING_EMPTY` distinguishes a failed post-click binding from a legitimate initial empty binding. `SELECTION_STOPPED` records the selection capability returning; `DRIVER_CLOSED` is the separate browser-close evidence.

The operator command is `node scripts/run-selection-diagnostic.mjs --select-observe-approved-once PRIVATE_SCOPE PRIVATE_EVIDENCE_DIRECTORY`. Do not invoke it without new approval. Scope expires within 30 minutes, uses a fresh UUID, and is consumed before opening a saved session. Prior inspection authorization files are checked too. The sender must remain PAUSED and batch rules OFF; contacted/UNKNOWN/in-flight recipients and cross-account ledgers are rejected. This command reads review/history and manages its device lease; it creates no contact attempt, quota consumption, collection or model call. Lease release requires confirmed owned-process stop.

Navigation is bounded to the production account check (`/explore`, exact self profile), then the scoped post. At most one reply-control opening is allowed. Restriction, uncertain identity, unknown binding or existing draft stops the operation. There is no fallback click, DOM state fabrication, timed send-tool cancellation, input, submission or retry.

Delivery checks include real SDK registration/schema tests, one-shot/concurrent/failure engine tests, TypeScript transport boundaries, and the real shared Rod selector on synthetic Chromium pages with all requests intercepted and a deny-network proxy. Browser fixtures prove one physical click followed by zero input/submit events on desktop and 390px, and stop behavior for empty binding, draft, identity changes and restrictions. These are offline capability tests, not evidence about a live platform handler or delivery. The production selector's live root cause still requires the new bounded diagnostic.

Historical `attemptedAt` denotes dispatcher entry, not platform submission. For a failed predecessor the diagnostic operator now calls the existing immutable recovery-chain verifier under the contact lock and additionally rejects every input/submit stage. It retains all prior rows and refuses UNKNOWN, CONFIRMED, reserved, disconnected or incompletely logged history. This operator-only correction does not change the MCP candidate or enable sending.
